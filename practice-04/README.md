## Перенос и организация кода

| Модуль | Назначение |
|---|---|
| `data.js` | Без изменения перенесены общий набор и шесть задач варианта 7 из ПР3 |
| `task-service.js` | Перенесены операции ПР3; добавлена `updateTask`, которая сохраняет id и completed |
| `task-selectors.js` | Фильтры ПР3, исходный массив не меняют |
| `task-view.js` | Безопасный вывод через textContent; в карточку добавлено действие edit |
| `form-validation.js` | Чистая проверка id, названия и приоритета; возвращает все независимые ошибки |
| `task-storage.js` | JSON, версия 1, схема задач, уникальность id, перехват ошибок storage |
| `main.js` | Состояние списка, фильтра и формы; связывает события, сервис, сохранение и отрисовку |

`storage` передаётся аргументом: модуль можно проверить без глобального window и с имитацией недоступного хранилища. Корректный синтаксис JSON не гарантирует правильную версию, типы полей и уникальность id, поэтому после JSON.parse проверяется схема.

## Эксперименты с формой и JSON

Прогноз в таблице — ожидаемое поведение; фактические значения получены в Safari через дополнительную страницу `examples/verify-scenarios.html`. Протокол: [scenarios.json](./reports/scenarios.json).

| Эксперимент | Ожидание | Фактический результат |
|---|---|---|
| Пустое обязательное поле | Браузер не вызовет submit | nativeValid=false, submits=0 |
| Только пробелы | required пропустит, прикладная проверка отклонит | submit вызван, ok=false, ошибка title |
| FormData | Значения останутся строками | typeof id и title — string; нормализованное название без краевых пробелов |
| localStorage и JSON | Записывается строка | storedType=string; объект восстановлен через JSON.parse |
| Повреждённый JSON | Ошибка и безопасный исходный набор | ok=false, source=fallback, четыре исходные задачи |

В основной форме preventDefault отменяет переход страницы; FormData читает поля, validateTaskDraft нормализует их, addTask/updateTask повторно защищают модель. При ошибке данные не меняются и запись в storage не выполняется. При редактировании disabled-поле id не попадает в FormData: используется editingId.
