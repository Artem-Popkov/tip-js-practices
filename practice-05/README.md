## Эксперимент с очередями

Прогноз до запуска: **A B C D E F**. Фактический вывод в [протоколе](./reports/own-checks.txt) совпал. A, B и C выполняются синхронно; D — обработчик уже разрешённого Promise, E — продолжение после await, F — задача таймера после микрозадач. Задержка 0 не означает немедленное выполнение таймера. Без обработчика D соответствующая запись исчезнет, оставшийся порядок A B C E F сохранится.

## Наблюдение HTTP

| Запрос | Ожидание | Факт |
|---|---|---|
| GET /health | 200, статус ok | Получен 200, JSON |
| GET /tasks/25 | Одна задача | id 25, «Исправить обработку ошибок», completed=true, high, categoryId=2 |
| GET /tasks/999 | 404 | ok=false, TASK_NOT_FOUND, details.id=999 |
| GET /tasks?completed=false&priority=high | 3 задачи | id [4,13,34], total=3 |

Content-Type в полученных ответах: `application/json; charset=utf-8`. Полные URL, статусы, response.ok и payload зафиксированы в own-checks.txt. Запросы выполнены реальным fetch; это не проверка CORS браузера. Для КР2 запросы дополнительно выполнены из браузера при запущенном API ПР5 на 5505.

## Организация кода

| Файл | Назначение |
|---|---|
| api/server.mjs | Готовый локальный API преподавателя |
| src/api-client.js | URL, GET, Accept, Response, HTTP-статус, JSON, тайм-аут и отмена |
| src/task-api.js | Допустимые фильтры, маршруты, схема задач/категорий, Promise.all |
| src/variant.js | Вариант 7 и q=провер |
| src/main.js | Консольная демонстрация и обработанный запрос отсутствующей задачи |

fetchFn передаётся явно для модульных проверок без сети. URL строится через URL/URLSearchParams: null/undefined/пустая строка пропускаются, false и 0 сохраняются, входной query не меняется. Проверяются абсолютный HTTP(S)-адрес без query/hash, функция fetch и положительный целый timeoutMs.

Каждый запрос получает Accept: application/json и AbortSignal. Таймер действует до окончания чтения тела; в finally он очищается и обработчик внешней отмены удаляется. HTTP-статус проверяется до формата успешного тела. Ответ 204 превращается в null, остальные успешные ответы должны содержать JSON. Повреждённый JSON сохраняет исходную ошибку в cause.

## Классификация ошибок

| Сценарий | Ожидаемый kind | Фактический результат |
|---|---|---|
| Задача 999 | http | status=404, code=TASK_NOT_FOUND, details={id:999} |
| completed=yes через общий клиент | http | status=400, code=INVALID_QUERY |
| /debug/error | http | status=503, code=SERVICE_UNAVAILABLE |
| /debug/invalid-json | invalid-response | kind=invalid-response |
| /debug/text | invalid-response | kind=invalid-response |
| Остановленный API | network | kind=network; после повторного старта запрос успешен |
| Задержка 120 мс при timeout 10 мс | timeout | kind=timeout |
| Внешний AbortController | aborted | kind=aborted |

Все случаи фактически выполнены и записаны в own-checks.txt. Неверные фильтры доменного метода отклоняются до запроса через TypeError; серверная ошибка completed=yes отдельно проверена общим клиентом.

## Доменный API и общий сценарий

getTasks() вернул 12 задач: `[1,4,7,10,13,16,19,22,25,28,31,34]`. Фильтр completed=false, priority=high вернул `[4,13,34]`. getCategories вернул категории 1 «Учёба», 2 «Проект», 3 «Организация». loadInitialData параллельно начинает запрос списка и категорий.

После JSON.parse проверяются поля задач и категорий, положительные безопасные id, длина названия после trim, boolean completed, разрешённый priority, categoryId, отсутствие повторяющихся id и соответствие meta.total длине массива. Для совместной начальной загрузки проверяется наличие категории каждой задачи.

На общем сценарии API доступен, получены 12 задач и три задачи по фильтру, параллельная загрузка успешна, 999 обработан как http/404. После закрытия API получен network; повторный старт вернул доступ к 12 задачам.

## Последовательная и параллельная загрузка

Каждый запуск использует два запроса /debug/delay?ms=120. Прогноз: последовательное ожидание около суммы задержек, параллельное — около одной задержки плюс накладные расходы.

| Сценарий | Запуск 1, мс | Запуск 2, мс | Запуск 3, мс |
|---|---:|---:|---:|
| Два последовательных await | 253.1 | 246.4 | 246 |
| Promise.all | 123.9 | 125.2 | 123.3 |

Это измерения конкретного запуска, не обещание одинакового ускорения в любых условиях. В прикладной код искусственные задержки не добавлены.
