## 4. Модель данных и функции

Модель задачи: `{ id, title, completed, priority }`. `id` — положительное безопасное целое число (`Number.isSafeInteger`), уникальное в пределах списка. `title` — строка, после `trim()` от 1 до 100 символов. `completed` — булево значение, при создании всегда `false`. `priority` — строго `"low"`, `"medium"` или `"high"`, по умолчанию `"medium"`.

Файлы: `data.js` — исходные данные (`demoTasks`, вариант); `task-service.js` — девять прикладных функций без вывода в консоль; `main.js` — сценарии и вывод результатов; `checks.js` — готовые автоматические проверки.

Функции чтения (`findTaskById`, `getPendingTasks`, `getTaskTitles`, `getTaskStats`) возвращают данные напрямую. Функции изменения (`createTask`, `addTask`, `setTaskCompleted`, `renameTask`, `removeTask`) возвращают объект результата: `{ ok: true, ... }` при успехе или `{ ok: false, error: "..." }` при ожидаемой ошибке — программа не прерывается исключением.

**Почему id не равен индексу:** индекс — это текущее место элемента в массиве, оно меняется при удалении соседних записей. `id` — устойчивый идентификатор конкретной задачи, который не меняется, пока задача существует. Поиск по `id` через `tasks[id]` был бы в корне неверным.

**Почему getTaskStats возвращает число, а не строку с процентом:** число можно использовать дальше в расчётах (сравнивать, суммировать). Округление и добавление знака `%` — это часть отображения, а не вычисления, поэтому `toFixed(1)` вызывается только в `main.js` перед выводом.

**Какие объекты копируются при изменении задачи:** при `setTaskCompleted` и `renameTask` создаётся новый массив (через `map`) и новый объект только для изменяемой задачи (через spread `{ ...task, поле }`); остальные объекты массива переиспользуются без изменений, так как они не редактировались.

## 9. Вывод

По сравнению с ПР1 логика перешла от отдельных переменных к массиву объектов и функциям с чётким контрактом: каждая операция изменения возвращает `{ ok, ... }` вместо того, чтобы прерывать программу исключением. Неизменность входных данных проверена через `map`/`filter`/spread — они всегда строят новые массивы и новые объекты для изменённых записей, а не трогают исходные. Самой показательной оказалась ошибка в эксперименте 2: пропущенный `return` в стрелочной функции с фигурными скобками — код выглядит рабочим, но результат вычисления просто нигде не сохраняется.
